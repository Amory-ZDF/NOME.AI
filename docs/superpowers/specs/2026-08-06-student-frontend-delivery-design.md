# NOME.AI 学生端前端功能闭环设计

- 日期：2026-08-06
- 状态：已批准
- 适用目录：`Student_Frontend/`
- 产品依据：共享飞书文档中的学生端要求，以及仓库现有 `README.md`、`API_INTERFACE.md` 和页面实现

## 1. 目标与边界

本轮在不重做队友视觉设计的前提下，把现有 React/Vite 演示页面补成可运行、可验证、可逐步接入真实后端的学生端前端闭环。学生始终能够回答三个问题：现在应该做什么、为什么做错、是否真的在进步。

本轮包含：任务管理、渐进式练习、练习总结与错因诊断、错题本、笔记与学习资料、题库、知识图谱、成长反馈、奖励和偏好设置。所有读取和写入均通过既有 API 适配层，Mock 模式下提供稳定且可持久化的等价行为。

本轮不新建真实后端，不实现真实 OCR、LLM 推理、文件云存储、登录鉴权或教师端通知服务。这些能力保留明确接口和可演示的 Mock 结果。IELTS 第一阶段聚焦 Reading；Writing 自动评分和代写相关能力暂不扩展。

## 2. 保留现状

- 保留现有路由、TopNav、页面结构、Tailwind 设计令牌、卡片密度和响应式布局。
- 不进行与功能无关的重构，不改动教师端。
- 当前英文界面保持英文，不在本轮引入全量国际化。
- 页面可加入必要的表单、确认框、加载态、错误态和空状态，但复用现有组件与样式。

## 3. 当前问题

1. 项目只有 `build`，没有单元或交互测试入口。
2. 多个页面直接读取 `mockData.js`，真实后端模式下无法完整替换数据源。
3. Store 中写操作多为 fire-and-forget；请求失败时没有回滚、错误提示或重复提交保护。
4. Mock 状态刷新后丢失，无法验证连续学习流程。
5. “生成变式题”“修改分类”“富文本工具”“上传拆题”等若干入口目前只显示提示，未形成可验证状态变化。
6. 知识图谱、进步数据、奖励和动态学生模型主要是静态展示，没有从学习行为更新。

## 4. 总体架构

数据流固定为：

```text
Page / Component
      ↓ user intent
AppStore actions
      ↓ validated command
API endpoint adapter
      ↓
Mock repository + local persistence  /  future REST backend
      ↓ normalized result
AppStore state
      ↓
Page / Component
```

页面只负责展示和收集用户意图。可独立验证的排序、判分、提示解锁、错因统计、掌握度更新和任务调整逻辑放在纯函数模块中。`AppStore` 负责异步状态、跨页面会话、乐观更新与回滚；`src/api` 保持真实后端与 Mock 的唯一切换点；Mock 数据存储通过带版本号的 `localStorage` 持久化并支持测试重置。

不进行一次性大重构。每完成一个功能模块，只抽取该模块需要的领域逻辑和 API；页面现有 JSX 与样式尽量原位保留。

## 5. 功能模块与交付顺序

### 模块 0：测试与状态基础

- 引入 Vitest、React Testing Library、user-event 和 jsdom。
- 增加 `test`、`test:watch` 脚本和统一测试初始化。
- 建立 Mock repository、状态版本、重置机制和 API 错误包装。
- 保证现有首页与路由基线不变。

### 模块 1：任务与时间管理

- 任务优先级规则固定为教师任务高于 AI 推荐；同时考虑截止时间、逾期、可用时间、预计时长和薄弱知识点。
- 完成任务后保留可查看的完成记录，不直接删除。
- “无法完成”收集原因、可用时间和建议日期，生成调整请求并展示提交结果；Mock 模式保存该请求。
- 支持 All、Pending、Overdue、Completed 筛选，并给出下一项建议任务。

### 模块 2：渐进式练习

- 必须先提交有效尝试，错误后才解锁帮助。
- 六层帮助依次为：确认题意、相关知识、下一步方法、关键步骤、完整过程、独立变式题。
- 记录每次尝试、用到的最高提示层级、在哪一层独立解决、耗时和手写模式。
- L6 真正生成可练习的变式题并进入任务/题库，而非仅弹出提示。
- A-Level 练习同时呈现理解层和得分层；IELTS Reading 记录文章证据与重复错误模式。

### 模块 3：总结、错因诊断与错题本

- 错因统一为知识、方法、计算、阅读理解、执行、表达、习惯七类。
- 错题卡包含错在哪里、为什么错、关联知识或能力、是否重复、提示依赖程度。
- 总结页从真实会话计算准确率、错因分布、知识关联和下一步任务。
- 错题去重并累计复发次数；独立重做不提供提示；至少一次独立答对后才允许标记掌握。
- 学会后安排变式验证，避免仅凭一次正确直接完成闭环。

### 模块 4：笔记与学习资料

- 支持新建、编辑、搜索、标签、版本、文件上传流程和自动分类确认。
- 文件类型覆盖课堂笔记、教师材料、作业、历年题、Mock、Mark Scheme、IELTS 材料以及手写草稿/错题照片。
- Mock OCR 输出可编辑内容、科目/考试局/章节分类、知识点和错题关联。
- “一键整理”产生可撤销的真实状态变化；分类修改、题答拆分和笔记关联可验证。
- iPad 手写、圈画和试卷还原在本轮以接口与可演示状态表示，不模拟真实笔迹识别模型。

### 模块 5：题库

- 搜索、科目、难度、题型和作答状态筛选全部基于 API 数据。
- 智能推荐理由来自薄弱知识点、最近错因和待验证掌握项。
- 上传试卷形成“处理中—待确认—已入库”状态，并提供拆题确认，不再只新增提示任务。
- 题库题目均能进入有效练习；不存在的题集给出可恢复错误态。

### 模块 6：学习档案、知识图谱与激励

- 知识点状态为已掌握、模糊、误解、未学习，并保留证据、更新时间和置信度。
- 即时更新练习行为，日更新任务/习惯，周更新趋势；所有标签都可解释且不是固定人格判断。
- 知识图谱关联前置、同类和延伸知识，以及相关笔记、错题和练习。
- 进步展示同类错误减少、从不会到掌握的天数、提示依赖下降等行为结果。
- 奖励复习、独立完成变式和主动求助；不使用排名或同伴比较。
- 语气滑杆、每日目标和提醒设置持久化，并影响后续反馈文案。

## 6. 状态与接口规则

- Bootstrap 返回完整前端初始状态；缺少非关键字段时使用显式默认值，关键标识缺失则进入错误态。
- 所有写操作返回 Promise。提交期间禁用重复动作并显示轻量加载状态。
- 可安全回滚的动作使用乐观更新；API 失败时恢复旧状态并显示可重试提示。
- 会话、任务调整、错题重做、上传任务和设置均在 Mock repository 中持久化。
- 页面不得新增对 `mockData.js` 的直接依赖；迁移到某模块时清除该模块页面已有的直接依赖。
- API 契约扩展必须同步更新 `Student_Frontend/API_INTERFACE.md`。

## 7. 错误与边界处理

- 空白、纯符号或明显敷衍答案不能提交，但必须给出清晰可恢复提示。
- 无效路由参数、过期练习、缺失会话和文件处理失败均展示返回入口，不允许空白页。
- 上传校验文件类型和大小；Mock 处理可被测试控制，不依赖随机计时。
- 异步操作在页面卸载后不得继续更新已卸载组件。
- 本地持久化数据版本不兼容时安全回退到种子数据，不破坏应用启动。
- 每个功能必须覆盖成功、校验失败和 API 失败三类路径。

## 8. 测试策略

每个模块按相同门槛交付：

1. 领域纯函数单元测试，包括排序、判分、提示解锁、错因统计和掌握度更新。
2. React 交互测试，覆盖该模块关键用户路径和失败路径。
3. `npm test -- --run` 全量通过。
4. `npm run build` 生产构建通过。
5. 使用 Playwright CLI 对本地页面进行浏览器冒烟测试，确认路由、主要动作和控制台无新增错误。
6. 视觉检查确认未发生非预期布局变化。

现有 favicon 404 属于基线小问题，将在测试基础模块中补齐，避免后续控制台噪声。

## 9. Git 交付协议

- 一个功能模块只包含该模块及必要基础设施的相关改动。
- 模块测试未全部通过时不提交、不推送。
- 通过测试后提交，提交信息明确标注模块；随后立即推送当前 `main`，满足“每完成一个小模块就 push”。
- 推送前再次确认工作树没有混入队友或无关改动。
- 设计文档单独提交；它不是功能模块，因此不作为模块测试完成的声明。

## 10. 完成标准

只有当六个学生端功能模块均满足各自交付内容、全量测试和构建通过、浏览器主流程验证通过、API 文档与实现一致，并且每个完成模块均已独立推送，学生端目标才视为完成。单个页面能打开、Mock 文案存在或构建成功不能替代上述功能验证。
